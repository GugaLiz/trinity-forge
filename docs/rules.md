# 三生炉：实现规则 v1

2026-11-06。交付为移动端竖屏 H5。源设计的冲突按开发计划第 2 节统一，以下是代码采用的确定行为。

## 配方、输入与实例

共 28 个产物，分为 9/12/7 三层。第一层包含 6 个无序两输入与 3 个无序三输入配方；第二、三层均为「产物实例 → 基础元素」的严格两输入配方。整体输入确认一次才匹配，不对前缀自动合成。因此 `[水,火,土]` 是温泉，`[蒸汽实例,土]` 是云。

输入最多 3 个，至少 2 个，重复元素需要对应的不同手牌实例；已投入的产物实例不能再次选择。反序或未知配方允许尝试，只扣 1 养分并结束回合，材料保留。对局中同名产物可以重复持有，合成时只消耗选中的实例。

每回合 6 张手牌：水、火、土各 1 张，余下 3 张由可复现的 xorshift32 随机数生成。每个新回合刷新手牌，剩余手牌不继承。预览和无效动作不抽随机数。

## 环境与支付

初始炉温/湿度/养分均为 5，范围 0–10。投入水使炉温 −1、湿度 +1；火使炉温 +1；土使湿度 −1；按输入顺序逐次夹到边界。投入产物不再次计算其历史组成。

成功合成扣基础养分 1，再扣配方表的资源成本。养分要足够支付完整成本，否则拒绝提交，不结束回合。炉温、湿度的配方成本可以使槽归零，触发失衡风险。

投入基础元素后的候选湿度为 0 时不能合成水系。水系名单：蒸汽、泥、雾、温泉、淤泥、云、雷云、沼泽、露、沸泉、灰烬泥、雨、森林、生灵、海洋。标签明确保存在配方数据，不根据名称运行时推断。

候选湿度 ≥8 时，有效配方抽取一次随机数，以 25% 概率失败。失败时仅扣基础养分 1，不提交候选环境变化、不消费材料、不生成产物。无配方不抽取该概率随机数。

调息占一个回合：养分 +2，温度与湿度分别向 5 靠近 1。调息同样执行生态回补和失衡判定；教学禁用调息。

## 固定结算顺序

1. 校验回合未过期、输入和实例、禁投元素、完整养分支付及湿度限制。
2. 匹配整体配方，计算候选输入环境，并按需做湿度失败判定。
3. 成功消费选中实例，应用元素变化、基础成本和配方成本，加入新产物；失败只扣基础养分。
4. 更新本局首次发现与炉记；重复发现不重复计节点分。
5. 生态回补：每个当前实例养分 +1，最多 +3；包括本回合新产物，被用掉的前置产物不再回补。养分上限 10。
6. 检查危险槽：温度/湿度为 0 或 10、养分为 0。满养分安全。三槽同时危险立即失败；否则存在危险槽时随机损失最多 1 个实例，生态为空仅记录反馈。持续极值每回合都会判定。
7. 结算后温度为 10，下一回合禁火；为 0 禁水。限制只由最近结算状态决定。
8. 第 12 回合后按本局发现数结算；否则推进回合，生成新手牌并保存快照。

养分回补前短暂为 0 不提前触发反噬。被摧毁实例本次已参与回补，从下回合起停止回补。失衡不清除发现记录。

## 胜负与计分

12 回合结束发现至少 8 种、且未全盘失衡，即通关。成绩为本局每个首次发现节点的表内分数之和，加安全槽数量 ×10，再加剩余养分；历史发现不影响本局通关与首见计分。已失败的局也记录其最终成绩。

教学是独立三回合：水+火→蒸汽、蒸汽→土→云、云→水→雨。按普通环境与成本结算，只接受当前目标配方；教程产物和成绩不带入正式局，也不计历史图鉴。

## 存档与后台

以一个版本化 JSON 原子写入历史、设置与最近已提交正式回合（含下回合手牌、随机数状态和炉记）。进入新局也保存初始状态。刷新后从首页继续；未提交投料不保存。结束时清除局中快照，保留历史与成绩。教学不做局中恢复。

后台暂停音频和装饰动画；回合逻辑同步完成，不依赖动画、计时器或前后台时间流逝。重复命令必须携带正确回合数，旧命令不重复扣费。存储损坏会丢弃无效快照；存储不可写时提示无法保存，仍可继续玩。

合成确认后立即完成逻辑与存档，再播放约 1.3 秒的炼化演出并展示结果确认面板。面板明确列出输入、输出、发现得分、结算前后资源及反噬；动画本身不触发第二次结算。演出期间禁止关闭和再次合成，结果可主动确认；减少动态时只短暂展示状态，保留完整结果反馈。刷新会跳过尚未展示完的演出，恢复最新提交回合。
